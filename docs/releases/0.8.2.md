## Shared screen textures for crowds

Screen fabrics can now share a small set of animated phase textures instead of generating and uploading one texture per garment. The built-in stage uses four phases automatically. Custom scenes can use the same mechanism through `ScreenTexturePool` from `@actors/three`.

```ts
const screenTextures = new ScreenTexturePool(4);
const resident = await Character.load({ pack, renderer, materials: nodeMaterials, screenTextures });
// Pass the same pool to all residents. Once per scene frame, before actor updates:
screenTextures.update(dt);
for (const resident of residents) resident.update(dt);
```

For existing characters, use `character.actor.setScreenTexturePool(screenTextures)`. Future garments join the pool too. This works with the normal WebGL kit and the WebGPU node-material kit, without a custom material wrapper.

- At most one pixel generation/upload per used phase per 1/12 second; updating more actors does not advance the shared clock.
- Independent garment emission colours and colour reset.
- No recurring pixel generation for unused phases.
- Reference-counted textures: disposing one wearer does not invalidate other wearers; the last release disposes the phase texture.
- Separate pools have separate clocks. A paused wearer still sees updates to a phase shared with active wearers. Use `setScreenTexturePool(null)` for independent material animation, or stop advancing the pool to pause all phases.
- `sharedScreenTextures: false` disables automatic stage pooling. Direct `Character.load` and `ThreeActor` remain independent unless a pool is supplied; `shareWith` inherits its lead's pool unless explicitly overridden.

The exported `screenPixels` API remains available for applications that want their own texture management. Existing 0.8.1 asset packs remain compatible; this change requires only a package update.

## Validation and performance

Type checking, 134 unit tests, the production build and installed-tarball regression checks passed. The standard viewer smoke test and all eight future outfits on two adult body shapes passed. Browser checks used WebGL and the node renderer's WebGL fallback; native WebGPU was not verified here.

Tests cover 64 materials sharing four textures, clock isolation, throttling, tint isolation, switching pools, reference lifetime and shared state across installed main/WebGPU exports. A browser scene with four wearers confirmed twelve screen materials sharing four textures, each uploaded once per tick. Emissive glTF export still passes.

A local Node CPU benchmark of 32 screen materials measured roughly **10.1 ms per animation tick independently versus 1.6 ms pooled**, using the median of five 50-tick batches after warm-up. This measures pixel generation and update bookkeeping, not GPU uploads or total rendering time; results vary by machine.

See [the integration guide](https://github.com/ArndRosemeier/Actors/blob/v0.8.2/docs/using-actors.md#sharing-screen-textures-082).
