## What's new: faster character loading

Spawning characters is much faster, most of all from the second character on.

- **Dressing a character no longer re-cuts the skin once per catalog garment.** That cost about half a second per character, on every change.
- **Each pack is loaded once per page.** Every `Character.load` (and `Human.load`, `Animal.load`) with the same pack URL shares the mesh, morph targets, garments, clips and textures. Pass `fresh` to `Human.load` for a private copy.
- **One worker can serve every character.** Passing the same worker to several characters used to mix up their replies, and the worker reloaded the pack each time.
- **Photo skins:** characters with nearly the same blend share one 2k texture. `dispose()` now frees it.
- **New: `await character.compile(renderer, camera, scene)`** compiles the character's shaders ahead of time (`renderer.compileAsync`), so the frame that first shows it doesn't freeze.

Measured in headless Chromium, CPU time per character load: 1.4–1.8 s before, 0.4–0.8 s now, 70 ms for a look that was already loaded.

## How to use it in a game

```ts
const worker = new HumanWorker();                        // one worker for all characters (or none)
const character = await Character.load({ pack, renderer, worker, config });
await character.compile(renderer, camera, scene);        // before adding it: no first-frame stall
scene.add(character.object);
```

- Load one or two typical characters behind the loading screen. That loads the pack and compiles the common shaders once.
- New garments, hairstyles and add-ons compile their shader the first time any character wears them. Later characters reuse it.
- More in the generator README, "Spawning many characters quickly".
- To time it on your own machine, open `bench.html?n=8` (with `&compile`, `&same`, `&worker` or `&webgpu`) on the demo site or the dev server.
