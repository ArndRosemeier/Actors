## Shared screen frames and sheer hosiery

- Export `screenPixels(timeSeconds, data?)` and `SCREEN_TEXTURE_SIZE` from `@actors/three`. Applications can use the same colour-independent pattern for their own shared phase textures. The optional RGBA8 buffer is updated in place.
- Correct the imported `stockings` and `fishnet-stockings`: neither now carries `hidesBaseVertices`. Their open textures retain the skin and lower clothing layers beneath them. Opaque socks keep their existing coverage masks.
- Extend installed-package checks to verify the public pattern generator matches built-in screen frames, reuses the supplied buffer, and that the imported sheer garments preserve actual body geometry and lower layers at full and medium detail.

The WebGPU entry-point screen registry bug was already fixed in **0.8.0** through shared release modules. That fix and its installed-tarball animation/tint regression check remain in place; storing state in material user data is not required.

```ts
import { screenPixels, SCREEN_TEXTURE_SIZE } from "@actors/three";

const pixels = screenPixels(0); // 64 × 64 RGBA8, sRGB
screenPixels(elapsedSeconds + phaseOffsetSeconds, pixels); // same buffer
```

This exports pixel generation, not an automatic shared-texture pool. Applications using their own screen materials manage phase updates, tint and texture lifetime; the standard Actors materials retain their per-material textures.

**Update the packages and asset pack.** Run `npx actors-packs` after installing 0.8.1. Old packs still contain the stockings' opaque masks, so keep any application workaround until the new pack is loaded. The shared-screen-frame API only requires the package update.

Validation: type checking and 131 unit tests passed, along with the installed-tarball build and screen/hosiery regression checks. Browser previews confirmed skin behind both sheer garments and retained opaque sock coverage.
