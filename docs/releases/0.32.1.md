## Memory: the face rig's CPU copy is released, dropped crowd meshes are freed

Found in MasterWorld (30 characters in a town, 100 re-dressings), measured on a GPU:

- **Face rig CPU copy.** A face rig's deltas are about 7.8 MB a character, and three keeps the array in `texture.image.data` (and the rig keeps it too) after the upload: 33 characters held 260 MB of JS memory, constant (a retention, not a leak). `Character` now uploads the rig's texture right after `setFaceRig` and drops both copies (`ThreeActor.releaseFaceRigData(renderer)`, `releaseFaceRigTexture` in `@actors/three`). A page with the face rig on is back to the memory it had without it. The slots stay (about 0.3 MB a character). Needs an initialised renderer (`initTexture`); without one nothing is dropped. A lost WebGL context cannot restore the texture; set the rig again then.
- **Leak: dropped crowd and part meshes.** `dropCrowd` and `setParts` disposed the geometry but not the renderer's draws, which keep the mesh through the shared material (about 3 geometries, 0.5 to 1 MB, per re-dressing; 151 after 100). They now dispatch the mesh's `dispose` event as well.
