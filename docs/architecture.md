# Architecture

```
MPFB2 data (CC0) --[tools/import-makehuman]--> actor pack --[@actors/core]--> shape --[@actors/three]--> three.js scene
                                                   |                                \--> glTF export (any engine)
                                         manifest.json + base.bin
                                         + targets/*.bin (streamed)
```

## Actor pack (`packages/core/src/format.ts`)

* `manifest.json`: meshes, proxies (garments), skeleton, skin, target index and species data (`extra.human`).
* `base.bin`: base positions, render meshes (split at UV seams, with a map back to shape vertices), skin weights, garment bindings.
* `clips/<library>/index.json` + `*.bin`: large clip libraries (e.g. CMU) kept out of the manifest and loaded on demand (`ActorRuntime.loadClipLibrary`); clips share bone lists and rest directions through named rigs and may be stored as int16 (`encoding: "i16"`).
* `garments/*.bin`: meshes with their own `blob` (the wardrobe). `ActorRuntime.loadMeshes` loads them on first use (also in the worker), `ThreeActor.addMeshes` creates their scene meshes, and the next shape evaluation fits them.
* `clips/*.bin`: retargetable motion clips (per bone: world-space rotation change since the source rig's rest pose + the bone's rest direction; root motion in hip heights). The source rig must have a real rest pose (glTF/Blender rest), never "frame 0 of the take".
* `textures/`: skin region masks, iris, photo skins (`extra.human.skins`, blended by `skinTextureWeights` and the adapter's `SkinComposer`), hair/brow and skirt textures.
* Meshes can be derived at load time (`subdivide: { source }`), so the subdivided body costs no download.
* `targets/*.bin`: one file per morph target, int16-quantized, sparse or dense, loaded on demand. Only the targets with a non-zero weight are fetched, so the first load is a few MB instead of ~38 MB.

## Runtime (`ActorRuntime`)

1. Species logic turns sliders into target weights (`@actors/human`: product of macro factors, MakeHuman-style).
2. `morph`: base + Σ weight · target (CPU, ~20 ms for a typical update).
3. `computeNormals` on shape vertices (so UV seams don't show).
4. `fitSkeleton`: each joint = mean of marker vertices, bone frames from head/tail/roll (Blender convention, so Blender-authored animation stays compatible).
5. `fitProxy`: garments are bound to body triangles (MakeHuman `.mhclo` scheme) and follow every morph. `evaluate(…, fit)` fits only the proxies (and stencil meshes) of the named meshes; `Human.fit` / `ThreeActor.neededMeshes()` pass what a character wears, so a runtime with a hundred garments loaded still shapes one person in a few milliseconds.
6. Subdivided meshes follow via their stencil (each new vertex is a fixed weighted sum of base vertices).
7. `surfaceDelta`: position/normal deltas for extra targets on top of a shape, used for GPU face morphs.
8. `Retargeter`: plays a clip on any fitted skeleton: each limb bone (arms, hands, fingers, legs, feet) is first swung (shortest arc) onto the source rest direction, then the recorded world-space change is applied. Torso, neck, head and clavicle bones are not swung, because each rig places them differently (aligning them tilted the pelvis and lifted the shoulders); they keep the target's own rest posture and only get the change. This is the standard "align rest poses, copy world rotations" retarget.

All of it is synchronous after targets load and has no DOM dependency. `serveRuntime` / `RemoteRuntime` (`packages/core/src/worker.ts`) run it in a Web Worker; the generator does this when given a worker, and the viewer does by default (`?noworker` turns it off).

`@actors/generator` sits on top: `Character` reconciles a JSON `CharacterConfig` onto a `Human` + `ThreeActor` (shape changes are merged into one worker job; look changes such as garments or hair are instant), `CharacterStage` is a studio scene and `CharacterEditor` a DOM panel that only uses the public `Character` API.

## Detail levels (`packages/core/src/lod.ts`)

`manifest.lods` lists the levels (name, suggested camera distance, the bones that still animate, whether to merge). Every level draws from the same `ActorShape`, so morphs, garment fitting and the skeleton carry over and switching costs nothing:

* `MeshDef.lods`: the levels a mesh is drawn at (lashes, teeth and tongue only at full detail).
* `MeshDef.lodOf`: a stand-in drawn where the named mesh is not (the base-mesh body for the subdivided one at "Medium", MakeHuman's 741-vertex proxy body at "Crowd"). The proxy body is bound to the base mesh like a garment, so it follows every slider, and shares the skin UV layout.
* `MeshDef.simplified`: reduced triangle lists over the same render vertices, computed by the importer with meshoptimizer (UV seams and hem cuts kept). Adapters only swap index buffers.
* `LodDef.bones`: the crowd level animates no finger bones; `lodBoneMap` / `remapSkin` move their weights to the hand.
* `LodDef.merge`: `mergeMeshes` / `fillMerged` build one mesh from the body and garments (the adapter colours garments by their tint or mean texture colour and keeps the skin texture), so a crowd actor is one draw call plus its hair.

## Renderer adapter (`@actors/three`)

One `SkinnedMesh` per pack mesh that is shown, sharing one `Skeleton`: meshes of optional garments and hairstyles are only made (and filled from the last shape) the first time they are shown, so crowds sharing one runtime don't each carry buffers for the whole loaded wardrobe. Visibility changes (`setVisible`, `setConcealed`, `hidePackMeshes`) are applied together by `flushVisibility()`, the next `update`, `applyShape` or `setLod`, so dressing a character costs one pass over the skin-hiding instead of one per garment. When the shape changes, vertex buffers are rewritten and the skeleton is re-bound in place; running animations are re-baked against the new bind pose.

Materials (`materials.ts`) patch three's built-in shaders: hair cards (alpha to coverage, luminance-preserving recolour), leg colliders for skirt-skinned garments (`colliders.ts`), skin (mask tints, brows, pores, wrapped diffuse, procedural vulva detail), eyes (iris recolouring), lashes, cloth (weave or garment normal maps, per-pixel hem cut from the `clip` attribute, luminance-preserving recolour) and dual-quaternion skinning on all of them, including the shadow pass. `setLod(level)` / `updateLod(camera)` switch the detail level: index buffers per level are cached, stand-ins swap visibility, and the crowd level hides body and garments behind one merged `SkinnedMesh` (`crowd` material in the kit, linear skinning) and drops finger tracks from the playing clip. Two morph channels per face mesh ("expression", "blink") are filled from `surfaceDelta` and blended every frame.

## Robots

`@actors/human` robot.ts builds a robot from an evaluated human shape (`Human.robotConfig` makes every `evaluate` build it too; with a worker this runs as the `robot` shape task of `serveRuntime`, so the parts arrive with the shape). The skin is split into one region per bone by skin weights (twist bones join their parent, clavicles the chest); each region is clipped where its bone stops dominating by a margin, Taubin-smoothed and thickened into a closed shell rigid on its bone. The body surface is the inner frame (smooth skinning), the head is a helmet fitted per direction from the head centre (a low percentile of the skin distance in a cone, so the nose, lips and ears don't push it out). All of it is `PartMesh`es of kinds plate, trim, frame, joint, visor and glow, drawn by the adapter's part materials; the pack meshes are hidden (`ThreeActor.hidePackMeshes`).

## Skeletons

`@actors/human` skeletal.ts builds an undead skeleton on the human rig (`Human.skeletalConfig`; with a worker it is the `skeletal` shape task). No CC0 skeleton fits a rig that follows body sliders, so the bones are generated: each bone is a set of signed-distance primitives (ellipsoids, tapered capsules, discs, triangles and triangle ribbons for flat bones, swept tubes for ribs and clavicles) blended on a grid turned along the bone and meshed with Surface Nets (sdfgrid.ts). Every piece is rigid on one rig bone, so all clips and garments work. Placement comes from the fitted rig and the body surface: stature and robustness scale the bones, the vertebrae follow the back line, the rib cage and pelvis are fitted to the torso outline, and the skull is modelled in a canonical space (eye midpoint origin) and mapped onto the head with per-axis scales measured from the skin. Body morphs are neutralised for skeletons (weight, muscle, breasts) since there is no soft tissue. Wear is noise erosion plus stains in the vertex shade; lost bones are picked with a seeded RNG; eye and heart lights are `glow` parts. Parts are of kind `bone` (adapter material in packages/three parts.ts); the body meshes are hidden but garments stay (`hidePackMeshes("body")`), and race horns and tusks are kept. About 0.5 M triangles, ~2 s per build (the `RES` constant trades detail for speed). Check with `apps/viewer/scripts/skeletons.mjs`.

## Library animals (`@actors/three` library.ts, `@actors/animal/library`)

Ready-made glTF animals from the private PrivateAssets repo (licensed, never in this repo). `loadLibraryAnimal` loads a `.glb` once per URL and root-motion mode (GLTFLoader with the meshopt decoder) and clones it with SkeletonUtils for each animal. At load, every clip's ground travel is found: the topmost bone whose position track moves away and doesn't come back is root motion (taken out of the track in model space, kept as an x/z path); otherwise the clip is sampled and the planted foot (the lowest leaf bone of those that reach the ground) slides back at the ground speed, plus any drift of the feet (clips whose root motion was lost in export). `update` turns the mixer's time steps into travel along those paths, weighted by each action's weight, across loop wraps. The catalogue is generated from PrivateAssets' meta files by `scripts/library/catalogue.mjs` (names, sizes, clip names, lengths and channel counts only).

## Animals (`tools/import-animals`, `@actors/animal`)

The dog, squirrel and cat packs are built around a skeleton instead of from a source mesh: Mesh2Motion's CC0 quadruped rig (the "fox" rig its dog, fox and cat models share) and its 13 clips are downloaded, and only the bones and animations are kept. They have the same bones, so every clip plays on each. `npm run import:animals` builds all animal packs (`-- --only cat` for one). The deer and the horse use their own rigs and clips the same way (Quaternius' deer, Mesh2Motion's horse); the horse pack adds a `saddle` bone for riders and optional tack meshes. The cow is a second body on the horse rig (same bones and clips), with horn meshes that morphs size and an optional collar and bell. The chicken uses Mesh2Motion's CC0 bird rig (bones only) with its own procedural clips; its folded wings are meshed as separate surface layers so they can open.

- **Body** (`dog.ts`, `sdf.ts`, `mesher.ts`, `bodymesh.ts`): the base dog is modelled on a Czechoslovakian Wolfdog photo. The rig is re-posed first (`turnChain`: neck carried high, head level, tail hanging; clips keep only 30 % of the fox's tail swing). Trunk, neck and skull are lofts (superellipse sections, deeper below the path than above, swept along a smooth path) drawn from the side profile of the coat, so the surface is the coat outline minus the shell fur; legs, ears, jaw, nose and muscle masses are ellipsoids and flattened round cones, with a carved mouth slit, almond eye sockets and cupped ears. Everything is joined with smooth unions, the "implicit skin around a skeleton" approach Spore and similar creature editors use. Surface Nets meshes the field at 3.5 mm, vertices are projected back onto it, relaxed, simplified to about 44k triangles (meshoptimizer) and Taubin-smoothed away from the mouth, eyes and ears.
- **Skinning and regions**: every primitive names its bones and a region (torso, leg, muzzle, ear, …). Skin weights come from soft part membership, inverse distance to the part's bones and diffusion. The same memberships give the per-vertex coat data (`coatA`..`coatE`: leg height, head, muzzle, tail position, ears, brows, bib, back, underside, mask, blaze, nose, lips, pads, eye rims, light mask), a fur flow direction and fur length; they ship as extra mesh attributes (`MeshDef.attributes`); `coatF` depends on the animal (dog and squirrel: nose coordinates for nostril detail; cat: tabby stripe coordinates and a lower-leg weight, `catcoat.ts`; deer: spot-row coordinates). One helper vertex per joint end makes the fitted skeleton follow morphs and bone scales exactly.
- **Breeds** (`targets.ts`, `@actors/animal`): proportions are bone scales (leg, back, neck, head, tail and ear length; leg bone thickness), the rest are morph targets (ear carriage, muzzle length/width/depth, stop, skull dome, chest depth, tuck-up, tail curl, bulk). Large rotations (dropped or folded ears, the curled tail) get a second target at half the angle, so sliders blend through it. `BREEDS` holds 12 dog presets plus a wolf and a fox; `mixParams` crosses two.
- **Squirrel** (`squirrel.ts`, `squirrelclips.ts`): the same rig and bone names, so every dog clip also plays on it. `placeBones` sets each joint from a side photo of an eastern grey squirrel (crouch with folded hind legs and flat feet, round head, tail up in an S); the body uses the same primitives at a 1.1 mm grid, with a `unit` of 0.3 that scales blend widths and marking sizes. It has its own procedural clips (idle, alert sit-up, eat, hop, run, tail flick), posed per frame with world-space bone turns and two-bone IK that keeps feet planted or moves them along step paths; they are stored in the normal retargetable clip format with the squirrel's rest directions as reference. Morphs: bulk, tail plume, cheeks. `SQUIRRELS` holds grey, red (ear tufts), fox and black presets; the coat adds frost (white hair tips), a banded and white-fringed tail, an eye ring, ear tufts and a finer fur grain. The viewer's `animals.html?animal=squirrel` shows it.
- **Fur** (`@actors/three` fur.ts): the body is drawn with the coat colours computed from the region data and the coat settings, then again as 16 instanced shells pushed out along the skinned normal and combed along the flow, with strands cut by 3D cell noise on the base-pack position (so they stay put through animation and breed changes). Shells are alpha-blended inner to outer, and strands smaller than a pixel fade to their average coverage, so distant fur is soft instead of sparkling. Locks are noise stretched along the flow; agouti coats get dark, streaky guard hair tips and a soft-edged saddle. Shells share the body's vertex buffers and are drawn at the full detail level only. Cat coats add mackerel tabby stripes (`tabby`), tortoiseshell patches (`patches`), light inner ears, a plain nose colour (`nose`), finer strands (`strand`), and the animal eye material takes an iris colour and a slit pupil (`iris`, `pupil`).
- **Cat** (`cat.ts`, `cattargets.ts`): a Maine Coon modelled on one side-on reference photo. Points are measured in the photo's pixels (`ph`), the rig is fitted to the photo's joints (`reachChain`, `placeBone`: hips, neck, head, jaw, tail), the trunk, neck and skull lofts are drawn from the photo's silhouette, and the eyes sit behind almond lid openings (`lens`, two intersecting spheres). Whiskers are thin tubes rigid on the nose and head bones (`DogBody.whiskers`, mesh `whiskers`). `DogBody.unit` (0.5 for the cat) scales the fixed distances in skinning and coat regions. Cat presets are `CAT_BREEDS` in `@actors/animal` (`Animal.presets` picks by species; `Animal.supports` tells which shape values the pack has morphs for).

### Deer

The deer pack (`npm run import:animals`, same importer) uses the skeleton and 13 clips of Quaternius' CC0 low-poly Deer (Ultimate Animated Animals pack) as its blueprint: idle (three variants), eating, walk, gallop, leap, jump, headbutt, kick, two hit reactions and death. Its mesh is not used.

- **Rig** (`deer.ts`, `quaternius.ts`): the pack's `.gltf` (embedded buffer) is repacked as GLB for the shared reader. The unweighted root and the IK pole targets are dropped; the pastern and hoof bones, which are IK targets parented to the armature in the source, hang below the cannon bones (the IK chain ends at their head), so they follow the legs in every clip. The rig is scaled to a sika hind (0.82 m at the withers); the low-poly model's proportions already match the reference photo closely, so only the ears are raised and the tail is set to hang (`aimBone`). `Back` (the pelvis) is the root-motion bone.
- **Body**: modelled on a side photo of a spotted sika hind, like the dog: trunk, neck and skull lofts from the photo's side profile (top line, under line, straight crest and throat lines) with widths from the low-poly deer's cross-sections; scapula, upper arm, elbow, muscled forearm, knobbly carpus, slim cannons, fetlocks, dewclaws and cloven hooves with flat soles; thigh, hams, calf and Achilles tendon down to the point of the hock; large cupped ears; sunk almond eyes with preorbital glands; nose pad with nostrils; a short flat tail. Meshed at 3 mm, about 52k triangles. No jaw bone in the source rig, so the mouth is closed.
- **Coat** (`deercoat.ts`): the dog's coat channels where they fit, plus `coatF` (rump patch, position along the body, distance from the spine line in the cross-section, where spots grow). The fur material draws sika spots in rows beside a dark dorsal stripe, a broken pale flank line, the white rump patch with its black border and dark tail stripe, a greyer head and neck, eye ring, pale inner ears and white metatarsal tufts, all behind coat amounts that are 0 for dogs. Deer markings blend perceptually (in √ colour space).
- **Presets** (`@actors/animal` deer.ts): sika hind (the base), fallow doe, chital, red deer hind, roe doe, white-tailed doe; bone scales for legs, back, neck, head, ears and tail plus four morphs (bulk, belly, neck girth, long face). `Animal` is generic over the species, which comes from the pack (`Animal.load<DeerShape, DeerCoat>(url)`); the viewer shows the deer at `animals.html?animal=deer`.

## Adding another species

Write an importer that emits an actor pack, plus a small package (like `@actors/human` or `@actors/animal`) that maps that species' sliders to target weights and bone scales. Core and adapters are reused unchanged.
